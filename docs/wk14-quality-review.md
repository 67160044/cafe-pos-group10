## 2. จุดที่พบความเสี่ยง

| รหัส | ความเสี่ยง | สถานการณ์ที่จะเกิดปัญหาจริง | ระดับ |
| --- | --- | --- | --- |
| R1 | `authenticate` ใน `authMiddleware.js` **ไม่บังคับล็อกอิน** (ถ้าไม่มี token ก็เรียก `next()` ต่อ) แต่ถูกใช้เป็นตัวป้องกันเพียงตัวเดียวของ 17 endpoint (menu GET, orders ทั้ง 6, members ทั้ง 4) | คนที่ไม่ล็อกอินเรียก `GET /api/orders` เพื่อดูออเดอร์ทุกสาขา, `GET /api/members` เพื่อดึงชื่อ/เบอร์/แต้มสมาชิกทั้งหมด, `PATCH /api/orders/:id/status` เพื่อเปลี่ยนสถานะออเดอร์สาขาใดก็ได้ หรือ `POST /api/orders` โดยระบุ `branchId`/`userId` เองข้ามการล็อกสาขาของแคชเชียร์ (โค้ดล็อกสาขาเฉพาะเมื่อมี `req.user`) | **Critical** |

| R4 | รหัสผ่านเก็บและเทียบเป็น plaintext (`user.password !== password` ใน `login`, `createStaff` บันทึก `password.trim()` ตรง ๆ) | ถ้าฐานข้อมูลหรือ dump รั่ว ผู้ไม่หวังดีได้รหัสผ่านจริงของพนักงานทุกคนทันที | **High** |

## 3. การแก้ไขที่ทำจริง

**รอบที่ 1 จุดที่เลือกแก้:** R1 (Critical) และ R2 (High) เพราะความรุนแรงสูงสุด ยืนยันกับระบบจริงแล้ว และแก้ได้โดยไม่เปลี่ยนรูปแบบ response จึงไม่กระทบหน้าจอ (แก้ฝั่ง backend เท่านั้น ไม่ได้แก้ไฟล์ใน `public/`) แก้เมื่อ 17/10/2569 ใน 4 ไฟล์ของ `src/routes/` ซึ่งใช้ `requireAuth` และ `requireRole` ที่มีอยู่แล้วใน `src/middleware/authMiddleware.js`

### 3.1 โค้ดก่อน/หลังแก้

ก่อนแก้ (ตัวอย่าง `orderRoutes.js` ใช้ `authenticate` ซึ่งเรียก `next()` เสมอแม้ไม่มี token):

```javascript
const { authenticate } = require("../middleware/authMiddleware");
router.get("/", authenticate, orderController.getAllOrders);
```

หลังแก้ (`requireAuth` ตอบ 401 เมื่อไม่มี token ที่ถูกต้อง):

```javascript
const { requireAuth } = require("../middleware/authMiddleware");
router.get("/", requireAuth, orderController.getAllOrders);
```

และใน `authRoutes.js` เพิ่มการจำกัดสิทธิ์ให้รายชื่อพนักงานเห็นได้เฉพาะ admin (แก้ R2):

```javascript
// ก่อนแก้
router.get("/users", authController.listUsers);
// หลังแก้
router.get("/users", requireRole(["admin"]), authController.listUsers);
router.get("/employees", requireRole(["admin"]), authController.listUsers);
```

| ไฟล์ | การเปลี่ยนแปลง |
| --- | --- |
| `menuRoutes.js` | บรรทัด 8-9 (`GET /`, `GET /:id`): `authenticate` เป็น `requireAuth` |
| `orderRoutes.js` | บรรทัด 7, 8, 11-14 (ทั้ง 6 route): `authenticate` เป็น `requireAuth` |
| `memberRoutes.js` | บรรทัด 8, 9, 12, 15 (ทั้ง 4 route): `authenticate` เป็น `requireAuth` |
| `authRoutes.js` | บรรทัด 9-10: เพิ่ม `requireRole(["admin"])` ให้ `/users` และ `/employees` |

**หมายเหตุ:** ในรอบที่ 2 (หัวข้อ 3.3) route ของออเดอร์ สมาชิก และเมนูถูกปรับต่อให้จำกัดตามบทบาท (`requireRole`) ไม่ใช่แค่ `requireAuth` และ `orderRoutes.js` ไม่มี route `PUT /:id/status` แล้ว

เหตุผลที่มั่นใจว่าไม่กระทบหน้าจอ: ทุกการเรียก API ของหน้าจอผ่านตัวช่วยใน `public/js/auth.js` ที่แนบ `Authorization: Bearer <token>` เมื่อล็อกอินแล้ว ส่วนที่เรียกโดยไม่แนบ token มีแค่ `/api/auth/login` และ `/api/branches` ซึ่งไม่ถูกแก้ และหน้าจอไม่เรียก `/api/auth/users` เลย
